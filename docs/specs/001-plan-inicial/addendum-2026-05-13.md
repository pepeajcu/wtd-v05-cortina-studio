## 2. Desviaciones de `proposal.md`

### 2.1 Slugs reales en JetEngine (afecta §4.3 y §4.4 del proposal)

| `proposal.md` | Real en JetEngine | Donde se refleja |
|---|---|---|
| CPT `home` | slug `home-singleton` | `wp-config.json` → `cpt.home.slug` y `bridge-fields.json` |
| CPT `proyecto` | slug plural `proyectos` | `wp-config.json` → `cpt.proyecto.graphqlPlural` |
| Options Page `general` | slug `general` (coincide) | `wp-config.json` → `options.general` |

**Implicacion para queries:** los selectores GraphQL son `homeSingletons`, `proyectos` y (cuando se exponga) `general`.

### 2.2 Plugin propio reemplaza el modulo de la spec (afecta §5 #3)

`proposal.md` §5 pide instalar **JetEngine — WPGraphQL Integration**. Ese modulo **no existe** en JetEngine 3.8+ ni como add-on. Sin el, los CPTs de JetEngine no aparecen en el schema de WPGraphQL.

**Decision tomada:** se construyo `wordpress/plugins/cortinastudio-wpgraphql-bridge/` (PHP propio). Hoy en v3.0.0 (zips v1→v6 en el repo como historial). Hace dos cosas:

1. Filtro `register_post_type_args` con lista negra — expone automaticamente cualquier CPT no nativo de WP.
2. Lee `bridge-fields.json` y registra cada meta key via `register_graphql_field`.

Esto cumple la promesa de fabrica: el plugin se instala identico en cualquier cliente; lo que cambia es solo `bridge-fields.json`.

### 2.3 SEO: Rank Math, no WPGraphQL SEO (afecta §5 #5 recomendado)

`proposal.md` §5 recomienda **WPGraphQL SEO** (Ash Hitchcock). Ese plugin esta **descontinuado**.

**Decision tomada:** instalado **Rank Math**, que tiene integracion GraphQL nativa desde v1.0.54 sin plugins extra. Yoast quedo descartado porque requiere licencia Premium para exponer datos a GraphQL.

### 2.4 Mappers fusionados en los fetchers (afecta §4.5)

`proposal.md` §4.5 lista mappers como archivos separados:
```
lib/wordpress/mappers/homeMapper.ts
lib/wordpress/mappers/proyectosMapper.ts
lib/wordpress/mappers/generalMapper.ts
```

**Decision para Fase 3:** mapear inline dentro de cada fetcher (`getHome.ts`, etc.) hasta que aparezca duplicacion real que justifique el archivo separado. Si el mismo mapeo se necesita en una page distinta de home/landing, se extrae entonces.

### 2.5 Codegen apunta a schema local, no al endpoint (afecta §4.2)

Algunos servidores PHP (staging con Traefik/Docker) devuelven un BOM al inicio de las respuestas JSON. `@graphql-tools/url-loader` falla al parsear. Se anadio `scripts/fetch-schema.mjs` que hace introspeccion y guarda `lib/graphql/schema.json`. `codegen.ts` lee desde ese archivo local.

Tambien: un solo archivo generado (`lib/graphql/generated/index.ts`) en lugar de `types.ts` + `operations.ts` separados — fusion de los tres plugins (`typescript` + `typescript-operations` + `typed-document-node`) para evitar la dependencia `@graphql-codegen/import-types-preset`.

### 2.6 Plugin construido en Fase 2 (afecta §9 "lo que este plan NO toca")

`proposal.md` §9 dice: *"Plugin PHP `cortinastudio-wpgraphql-bridge` — se configura en Fase 2 via `bridge-fields.json` existente"*. Esto implica que el plugin ya existia.

**Realidad:** el plugin **se construyo dentro de Fase 2**. Paso por 6 iteraciones (v1 hardcoded → v3 production-ready). El alcance de Fase 2 fue mas amplio de lo que la spec asumio.

## 5. Camino concreto para cerrar Cortina Studio

Orden ejecutable de aqui en adelante (sin cambios al contrato del proposal, solo refinando lo pendiente):

1. Exponer Options Page `general` a GraphQL en el plugin (`register_graphql_field('RootQuery', 'general', { ... })`).
2. Crear `lib/graphql/queries/getGeneral.graphql`.
3. `npm run codegen` para regenerar tipos.
4. Crear `.env.local` con credenciales reales del WP de produccion.
5. Crear `lib/wordpress/getHome.ts` con schemas Zod inline para los 4 repeaters (`problems_cards`, `reels_selected`, `process_rotating_words`, `process_steps`).
6. Crear `lib/wordpress/getProyectos.ts` (sin repeaters — todos escalares).
7. Crear `lib/wordpress/getGeneral.ts`.
8. Migrar `app/[locale]/page.tsx` a RSC con `await getHome() + getProyectos() + getGeneral()` pasando props.
9. Actualizar props de las secciones; eliminar arrays `PROBLEMS`, `REELS`, `STEPS`.
10. Configurar webhooks salientes en WP apuntando a `/api/revalidate?secret=...` con body `{ "tag": "wp:home" }` (y analogos).
11. QA + checklist de Fase 5 del `task.md`.

Cuando ese paso 11 cierre, el repo queda probado como motor de fabrica con un cliente real.
