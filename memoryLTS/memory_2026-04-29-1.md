## Fase 2 — WordPress Headless: Plugin Bridge y configuración del backend

Sesión de trabajo documentada hasta abril 29, 2026. Cliente: Cortina Studio.

### Problema raíz: JetEngine no expone CPTs a WPGraphQL de forma nativa
JetEngine no añade `show_in_graphql = true` al registrar sus CPTs. Tampoco existe un plugin público mantenido ("WPGraphQL for JetEngine" no existe en Github confirmado). Solución: plugin PHP propio.

### Plugin v1.0.0 — hardcoded (anti-patrón de fábrica, reemplazado)
- Creado en `wordpress/plugins/cortinastudio-wpgraphql-bridge/`
- Exponía CPTs via `register_post_type_args` con slugs hardcodeados
- Verificado funcionando: `proyectos` devuelve datos reales (`"platform": "tiktok"`)

**Slugs reales confirmados en JetEngine (crítico):**
- CPT Home: slug `home-singleton` (NO `home` como se asumía inicialmente)
- CPT Proyectos: slug `proyectos` (NO `proyecto`)

### Plugin v2.0.0 / v2.1.0 — Auto-descubrimiento (versión actual)
Objetivo: instalar el mismo archivo PHP en cualquier cliente sin tocar código.

**Cómo funciona:**
1. Lee `wp_options['jet_engine_cpts']` para obtener lista de CPTs de JetEngine
2. Inyecta `show_in_graphql + graphql_single_name + graphql_plural_name` automáticamente
3. Lee posts internos de tipo `jet-engine-meta-boxes` para descubrir campos
4. Registra cada campo con resolver camelCase (escalares → String, repeaters → JSON string)
5. Panel admin en Settings → WPGraphQL Bridge muestra estado de detección

**Problema encontrado en v2.0.0:** JetEngine en esta instalación NO usa las claves estándar `jet_engine_cpts` ni post type `jet-engine-meta-boxes`. v2.1.0 añade auto-detección con múltiples candidatos + búsqueda por patrón en `wp_options` via SQL. Resultado de v2.1.0 al cierre de sesión: pendiente de verificación con panel de debug.

**Repeaters de JetEngine** se serializan como JSON string. Next.js los parsea con `JSON.parse()` en los fetchers.

### Decisiones de stack importantes
- **SEO:** Rank Math recomendado. WPGraphQL SEO (Ash Hitchcock) descontinuado. Rank Math tiene integración nativa con WPGraphQL desde v1.0.54 sin plugins extra. Yoast requiere Premium para GraphQL.
- **Webhook:** WP Webhooks de Cozmoslabs (wpwh). Versión gratuita suficiente. Trigger: `post_saved`, body: `{ "tag": "wp:home" }` / `{ "tag": "wp:proyectos" }` / `{ "tag": "wp:general" }`.
- **General Settings:** No son CPT sino JetEngine Options Page → guardado en `wp_options`, no en `post_meta`. Requiere query GraphQL custom en `RootQuery` (no expuesto aún).

**Why:** El plugin v1 tenía CPTs hardcodeados — anti-patrón para fábrica replicable. v2 fue necesario para cumplir el principio de "instalar y funciona sin tocar código".

**How to apply:** Al conectar WordPress en futuros clientes, instalar `cortinastudio-wpgraphql-bridge` directamente. Si el panel no detecta CPTs, revisar versión de JetEngine y usar la sección debug del panel. Verificar siempre los slugs reales de CPT en JetEngine → Custom Post Types → Edit → "Post Type Slug".
