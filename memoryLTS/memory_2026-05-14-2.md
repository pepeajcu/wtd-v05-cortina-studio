## Decisiones tomadas

- **Bloque `_options` con prefijo `_` en `bridge-fields.json`** en vez de un archivo separado o una clave hermana sin prefijo. Razon: mantiene un solo archivo de configuracion por cliente (regla de oro de la fabrica) y el prefijo `_` da una marca clara para skipear en el loop de CPTs. El plugin reserva ese namespace para meta-config futura (otras options pages, taxonomias, etc.).
- **Resolver con 3 patrones en cascada en lugar de uno solo.** Razon: JetEngine guarda options pages de forma distinta segun la configuracion del campo ("Save into wp_options" individual vs array agrupado), y no queremos exigir un patron al cliente. La cascada cubre los 3 casos comunes sin tocar la config del cliente. Trade-off asumido: 1-2 queries SQL extra cuando un campo cae en el patron 2 o 3.
- **Mantener el repeater como JSON string en el schema GraphQL** (consistente con repeaters de post_meta). Razon: el frontend ya tiene el patron `JSON.parse` + Zod en los fetchers; introducir tipos object reales en GraphQL para repeaters romperia esa convencion y obligaria a tocar codegen.
- **Bump de version a 3.1.0** (minor, no major). Razon: cambio aditivo — no rompe el comportamiento existente del plugin con CPTs ni con clientes que no usen Options Pages.
